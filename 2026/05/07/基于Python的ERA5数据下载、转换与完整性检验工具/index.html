基于Python的ERA5数据下载、转换与完整性检验工具

高效处理ERA5气象数据：基于Python的自动下载、转换(GRIB转NC)与完整性检验工具

在气象学、气候变化研究以及当下火热的 AI 气象大模型（如盘古气象、伏羲等）中，ERA5 再分析数据是不可或缺的“基石”。然而，在实际处理 ERA5 数据时，我们常常会遇到以下痛点：

  1. 下载不稳定：长时间跨度的批量下载容易中断或超时。
  2. 格式与颗粒度不符：官方下载的 GRIB 格式文件通常是按天或按月打包，而在实际模型训练或分析中，我们往往需要逐小时的 NetCDF (.nc) 格式。
  3. 数据易缺失：大规模下载后，很难用肉眼排查某一天是否漏下了某个时次的数据。

为了解决这些问题，我基于 Python 开发了一套轻量级的自动化工具流。本文将为你详细介绍这个由“下载 -> 转换 -> 校验”三大模块组成的完整方案。

注：本脚本只适用 ERA5 hourly data on pressure levels from 1940 to present 数据

🛠️ 工具流全貌

这套工具链包含三个核心 Python 脚本，职责分明：

  1. download_date.py：负责稳定、批量地按天下载数据，支持断点续传。
  2. convert_grib_to_nc.py：负责将打包好的日度 GRIB 文件，精细拆分并转换为逐小时的 NetCDF4 文件。
  3. check_missing_nc.py：负责在最后把关，扫码检查所有生成的 .nc 文件，输出缺失报告。

🚀 核心功能拆解

步骤 1：按天循环下载与断点续传 (download_era5_daily.py)

以往直接请求一个月或一年的数据，经常会遇到 CDS API 队列排队时间过长或网络中断导致前功尽弃的情况。

在这个脚本中，我们采用了按天循环的策略。它会自动将你要下载的时间段（例如 2017-01-29 到 2017-01-31）拆分为单天进行请求。

  • 断点续传：脚本会通过 os.path.exists 检查目录下是否已经有了当天的数据文件。如果网络中断，重新运行脚本即可，已下载的文件会自动跳过，省时省力。
  • 高度定制：你可以灵活配置所需的 16 种气象变量（如温度、相对湿度、风场等）、3 个气压层级（500, 700, 850 hPa）以及指定的空间经纬度范围（Area）。

步骤 2：GRIB 自动拆分为逐时 NC 格式 (convert_grib_to_nc.py)

很多科研人员习惯使用 NetCDF (.nc) 格式而不是 GRIB。更重要的是，我们通常需要 YYYYMMDD_HH.nc 这种单文件单时次的颗粒度。

本脚本基于 pygrib 和 netCDF4 库实现了数据的“庖丁解牛”：

  • 智能解析时次：自动读取 GRIB 中的 dataTime，无论当天的数据是 00:00 还是 23:00，都能被准确映射到相对小时（Hour since 当天 00:00）。
  • 符合 CF-1.8 标准：生成的 NetCDF 文件并非简单的数据堆砌，而是注入了完善的元数据（Metadata），包括标准的时间坐标系、经纬度、各变量的 long_name 和 units。这保证了生成的文件能被 Panoply、xarray 或 GrADS 等工具无缝读取。

步骤 3：数据完整性自动化校验 (check_missing_nc.py)

数据跑完了，怎么确认全不全？手动翻看成千上万个文件显然是不现实的。

校验脚本会自动推断处理的日期范围，并遍历检查：

  • 严重缺失：某一天的数据彻底没下下来。
  • 部分缺失：某一天缺少了几个特定的时次（例如少了 05 时和 12 时）。
    最终结果不仅会在控制台高亮打印，还会生成一份详细的 missing_files_check.log 日志文件，哪天缺了什么，一目了然。

⚠️ 避坑指南：环境与配置项

在运行本套脚本前，有几个极易踩坑的地方需要特别注意：

1. 新版 CDS API 的凭证配置 (2024更新)

如果你还在用以前的 UID:Key 格式去配置 .cdsapirc 文件，现在肯定会疯狂报错（如 401 Unauthorized）。
Copernicus 平台已经进行了全面升级，现在的 API Token 是一串 UUID 格式的 Personal Access Token。你需要前往新版 CDS 官网 注册并在个人主页获取新 Token，然后重新配置 .cdsapirc 文件：

2. 用户协议（Accept Terms）

即便你配好了 API 密钥，如果在网页端没有点过同意该数据集的使用条款，下载依然会被拦截（报 403 错误）。记得在网页端先手动尝试下载一次并点击 “Accept Terms”。

3. pygrib 库的安装

处理 GRIB 必不可少的 pygrib 库对 Windows 系统极不友好。如果你在 Windows 环境下开发，强烈建议不要使用 pip install pygrib。
推荐方案：

  • 使用 Conda 安装：conda install -c conda-forge pygrib
  • 或者直接在 Linux 系统 / Windows 的 WSL 子系统中运行转换脚本。

🎯 总结

这套 Python 脚本将繁琐的“下载、拆分、转码、校验”流程整合到了一个流水线中。你可以把它当作获取气象数据集的基础脚手架，根据自身研究需求（比如调整提取的气压层、下载地面单层数据等）进行简单的修改即可投入生产使用。

工具虽小，但能大幅减少气象科研中毫无技术含量的数据预处理时间。把时间留给更有价值的模型构建与数据分析吧！
