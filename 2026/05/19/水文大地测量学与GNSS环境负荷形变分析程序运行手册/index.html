水文大地测量学与GNSS环境负荷形变分析程序运行手册

🌍 水文大地测量学与 GNSS 环境负荷形变分析：项目实战与 PNAS 复现手册

编制目的：本手册旨在帮助研究人员（包括入门新手与跨界学者）快速理解 GNSS 水文负荷形变的核心概念，并提供一套打通了从“水文模型解析”到“实测处理与对齐扣除”的全流程代码管线。
科学目标：完整复现 Han et al. (2021) PNAS 论文中的核心图表（如 Figure 5 / Figure S10），通过 GNSS 观测与 GLDAS 模型比对，分离并量化地表洪水与地下水质量变化。

💡 第一章：项目背景与核心科学概念

1.1 为什么 GNSS（GPS）会上下浮动？

在毫米级的超高精度下，地球并非坚硬无比，而是像一个“充满气的厚皮皮球”，具有弹性。

  • 水文负荷（Hydrological Loading）：当雨季（如孟加拉国季风期）来临，大量的降水、洪水堆积在地表。水体极其沉重，会压迫地壳，导致 GNSS 台站向下沉降。
  • 地壳反弹：旱季水分流失，地壳重量减轻，便像弹簧一样向上反弹。

1.2 科学背景：2020 年孟加拉国特大洪水 (PNAS 论文解析)

根据 Han 等人发表在 PNAS 的研究，2020 年孟加拉国经历了史无前例的严重洪灾：

  • 现象：洪水爆发时间早、持续时间长。
  • 物理机制：研究发现，2020 年 5 月底的特级气旋 Amphan 提前倾泻了约 12 Gt 的降水，导致土壤层提前一个月达到饱和（Premature Soil Saturation）。随后的季风降雨无法渗入土壤，直接转化为强劲的地表径流（Runoff），引发了严重洪水。
  • GNSS 与 GRACE-FO 的作用：卫星重力（GRACE-FO）和地表 GNSS 台站观测到的是总水储量变化（包含土壤水 + 洪水/地下水）。
  • 我们的目标：利用 GLDAS 水文模型计算出“土壤湿度（Soil Moisture, SM）”造成的负荷沉降，然后从 GNSS 实测沉降中扣除它（GNSS - SM）。剩下的残余信号，就是由于洪水和地下水增加而导致的纯净形变！

🛠️ 第二章：环境与数据准备

在开始运行代码前，请确保本地计算环境配置完毕：

  • 软件环境：
    • Python 3.8+：需安装必备科学计算包：pip install numpy pandas matplotlib scipy netCDF4 mpi4py
    • MATLAB：用于运行经典的 GNSS 最小二乘时间序列分析 (LSF) 脚本。
  • 核心数据准备：
    1. GNSS 实测数据：存放于 ./pbo 目录（通常为 .pos 格式，pos数据共包含7列，分别代表：时间、N方向位移、E方向位移、U方向位移、N方向误差、E方向误差、U方向误差。）。
    2. GLDAS 水文模型数据：从 NASA 官网下载的全球水文网格数据（每日或每 3 小时的 .nc4 格式文件，如 0.25° 分辨率）。
    3. 台站列表：如 BD_sites.txt（包含孟加拉国等研究区域台站的经纬度）。

🚀 第三章：五步通关数据管线 (Workflow & Quick Start)

整个数据处理管线分为 “模型正演分支 (A)” 和 “实测处理分支 (B)”，最后在 “集成可视化阶段 (C)” 汇合。

🌊 分支 A：水文负荷正演（计算洪水质量引起的的弹性沉降）

[Step 1] 提取水文质量异常 (Mass Anomaly)

  • 使用脚本：gen_gldas_noah.py
  • 功能说明：读取 3 小时分辨率的 GLDAS/NOAH NetCDF 原始数据，计算选定时间段的等效水高 (EWH)，并扣除时间均值 (Temporal Mean) 获取质量异常，最后输出格网文件 (.nc)。
  • 关键配置修改：
    • gldas_directory：指向你下载的 GLDAS .nc4 存放路径。
    • start_year_tm ~ end_day_tm：设定计算均值和输出的时间范围（论文中为 2020.05.01-08.31）。
  • 执行方式：python gen_gldas_noah.py
  • 输出：output/Grid_Files/nc/GLDAS/convgf_*.nc

[Step 2] 球面卷积积分（形变正演）

  • 使用脚本：run_cn_gldas_noah.py
  • 功能说明：调用 LoadDef 的格林函数 (PREM模型)，将步骤 1 的质量异常网格与格林函数进行空间卷积，计算指定 GNSS 台站 (如 BNTL, CHNR) 的形变。
  • 关键配置修改：
    • sta_file：修改为你的台站列表文件 (../input/Station_Locations/BD_sites.txt)。
    • lsmask_type = 2：极重要！屏蔽海洋以避免海岸线插值导致的虚假水文信号。
    • loadfile_prefix：必须与步骤1生成的文件前缀严格一致。
  • 执行方式 (依赖 mpi4py 并行计算)：
    mpirun -np 4 python run_cn_gldas_noah.py (以4核为例)
  • 输出：output/Convolution/cn_LandOnly_*_PREM.txt

[Step 3] 格式化输出与基准对齐

  • 使用脚本：extract_loaddef_to_pos.py
  • 功能说明：LoadDef 输出的是地心直角坐标系/球坐标系混合结果。本脚本将其转换为标准的 North、East、Up 分量物理位移，并在时间上进行截取；同时执行背景均值归零。
  • 关键配置修改 (在脚本最下方的 config 字典中)：
    • input_dir：指向步骤 2 的输出目录。
    • station_list：填入需要处理的台站名。
    • bg_start_date / bg_end_date：定义零点基准段，建议与实测 GNSS 的基准时间一致。
  • 执行方式：python extract_loaddef_to_pos.py
  • 输出：生成标准的 .pos 文件，存放在 ./data/loaddef_soil_moisture/ 文件夹下。

📡 分支 B：GNSS 信号提纯（剥离构造与地震干扰）

[Step 4] 最小二乘法拟合 (LSF)

  • 使用脚本：lsf_main_custom.m
  • 功能说明：读取原始 GNSS 定位结果，通过最小二乘法 (LSF) 拟合并扣除构造运动长期速率 (Rates)、地震/仪器更换阶跃 (Breaks) 和震后松弛 (Explog)，仅保留环境负荷导致的周期项与残差。
  • 关键配置修改：
    • udir = './pbo'：指向你的原始 GNSS 存放目录。
    • components = {'N', 'E', 'U'}：设定需要提取的分量。
  • 执行方式：在 MATLAB 环境中直接点击“运行 (Run)”。
  • 输出：纯净时间序列文件 (.up, .north, .east)，自动存放在 ./neu/ (或你在配置里指定的 ./data/neu_lsf) 下。

🤝 汇合 C：顶刊级可视化（扣除负荷）

[Step 5] 负荷扣除与网格图渲染

  • 使用脚本：remove_sm_load.py
  • 功能说明：读取实测数据 (步骤4) 和模型数据 (步骤3)，利用 Pandas 进行 YYYYMMDD 精准对齐（剔除缺失天数）。执行扣除操作：GNSS-SM。并利用 GridSpec 布局，绘制上方散点、下方条形图无缝贴合的顶级学术图表。
  • 关键配置修改 (在 if __name__ == "__main__": 下方)：
    • 确保目录对应：dir_gnss (LSF结果), dir_sm (模型结果), dir_out (出图结果)。
    • 使用 remover.plot_grid() 传入自定义的 ylim 以适应不同方向的波动幅度。
  • 执行方式：python remove_sm_load.py
  • 输出：
    1. 对齐并扣除负荷后的时间序列纯文本数据（格式保留为时间、位移、误差）。
    2. All_Stations_{comp}_Grid.png/pdf：PNAS Figure S10 同款高精美多面板对比图。

📊 第四章：结果解读 (如何看懂 PNAS 风格图表？)

运行完 Step 5 后，程序会生成一张极具学术美感的子图。对照 PNAS 论文的思想，这样解读你的成果：

  1. 下半部分（浅蓝色条形柱）：
    • 代表 GLDAS 算出的土壤湿度（SM）水质量引起的形变量。随着季风和降雨，蓝色柱子向上飙升（土壤变重）。
  2. 上半部分（时间序列散点图）：
    • 🔵 蓝色空心圆 (GNSS 实测)：代表台站的总沉降量。你会发现，下方水分增多时，蓝色空心圆大幅向下掉落（被压弯），两者呈现完美的负相关。
    • 🔺 橙色实心三角 (GNSS - SM 修正信号)：核心结果！这是实测沉降扣除了土壤湿度负荷之后的残余信号。
  3. 科学推演（The “Aha!” Moment）：
    • 如果橙色三角依然呈现明显的下沉趋势（如 PNAS Fig 5B 所示额外下沉了 ~7mm），说明除了土壤里的水，地表还有巨大的额外水体（即洪水泛滥 Floodplain water 和地下水 Groundwater）。通过这个残余下沉量，我们就能成功反演出洪水的严重程度与动力学特征！

⚠️ 第五章：避坑指南与最佳实践 (Best Practices)

  1. 时间轴严格对齐 (Temporal Alignment) ⏳
    • 大坑：模型基准期和 GNSS 基准期不一致。
    • 解法：如果 PNAS 中采用 2020.05.01~05.31 作为均值零基准，你在 extract_loaddef_to_pos.py 中务必将 bg_start_date 和 bg_end_date 设为同一时段。否则直接相减会出现系统的常数偏移（曲线整体平移）。
  2. 海洋屏蔽 (Ocean Masking 务必开启) 🌊
    • 大坑：孟加拉国紧邻孟加拉湾，GLDAS 的陆地边界水文异常会被错误平滑插值到海洋上。
    • 解法：在 run_cn_gldas_noah.py 设定 lsmask_type = 2。如果不屏蔽，沿海台站的格林函数积分结果将被严重污染。
  3. 理解极性与物理相关性 (Polarity) 🧲
    • 牢记：质量增加 = 负荷变重 = 地壳下沉 (Up 分量为负)。降水与 GNSS 的 Up 垂直分量在物理图形上是镜像对称的（一上一下）。
