LGD反演与地壳负荷形变计算全链路程序用户手册

📖 GRACE-FO LGD 反演与地壳负荷形变计算全链路程序用户手册 (User Manual)

1. 系统概述 (Overview)

本系统是一套完全解耦的地球物理计算管线（Pipeline），旨在打通从卫星重力学到形变大地测量学的数据链路。
系统实现了以下核心闭环：

  1. 读取 GRACE-FO 卫星的星间视线重力差（LGD）观测值。
  2. 通过带有正则化约束的九宫格（Mascon）算法，反演出地表等效水高（EWH）时空演变。
  3. 将反演结果无缝注入地壳负荷形变（LoadDef）正演系统。
  4. 结合 PREM 地球模型格林函数，计算区域极端水文事件（如季风洪水）引起的 GNSS 台站三维弹性位移。

2. 系统管线架构 (Pipeline Architecture)

整个数据流分为 5 个独立但连贯的模块：
LGDInversionSuite.py ➔ export_ewhnpz_to_lgdtws_nc.py ➔ gen_lgd_tws.py ➔ run_cn_lgd_tws.py ➔ plot_ts.py

3. 核心模块与参数详解 (Step-by-Step Guide)

模块一：时变重力高频反演 (Inversion)

运行脚本：python LGDInversionSuite.py
功能描述：本模块是整套系统的“核心算法大脑”。它读取预处理好的 GRACE-FO 星间视线重力差（LGD）瞬时数据与卫星轨道状态向量，利用最小二乘法与 Tikhonov 多维正则化，将极度稀疏的单日重力测量值解算为地表高分辨率的等效水高（EWH）时空演变矩阵，并输出为自描述的 .npz 文件供下游调用。

全参数详解（对应脚本中 base_config 与 config 字典）：

1. 基础环境与轨道参数 (Base Configurations)

这些参数主要定义了数据来源与底层轨道积分的物理范围，通常设定一次后无需频繁更改。

参数名 推荐设置 (默认) 物理/程序含义
groops_workspace 你的本地路径(如’G:\GROOPS\PNAS2020Workspace’) GROOPS 工作空间目录。指向预先计算好的 GRACE-FO 卫星精密轨道数据。
lgd_results_dir 你的本地路径(如’G:\GROOPS\PNAS2020WorkspaceBase202005Field\LGDPostprocess\processed_results\GROOPS-NOAH_SM’) LGD 观测值目录。指向从 Level-1B 数据中提取的、且已扣除背景场（如 GLDAS 土壤水分）的残差 LGD 数据路径。
region_lon
region_lat		 (88, 92)
(22, 26)		 核心研究区边界。此处设定的为孟加拉国（Bangladesh）的经纬度边界框，用于在长长的卫星轨道中精准过滤出过境本区的有效时段。
track_lat_limit (-80.0, 80.0) 轨道纬度限制。截取 GRACE-FO 数据时的通用有效纬度范围（排除极地密集交汇区的噪点）。
orbit_interval 2 轨道采样间隔。默认 2 秒，完美兼顾空间采样密度与计算内存。
n_max 200 截断阶数。底层重力场球谐展开的最大阶数（Degree & Order）。200 阶足以捕捉约 100 km 级别的地表质量剧变细节。

2. 空间防漏与网格参数 (Spatial Mascon Settings) 🔥【核心设计】

参数名 推荐设置 (默认) 物理/数学含义
region_mode '9-caps' 空间防漏控制（Mascon 阵列）。这是复现 PNAS 结果的核心！
• 1-cap：仅反演核心区（灾难性设置，必然导致外围信号全漏入中心）。
• 9-caps：生成 $3 \times 3$ 的矩阵包围网（包含 1 个孟加拉核心区 + 8 个周边背景区）。通过联立方程组，让外围区域完美吸收印度/缅甸的洪水噪声，构建出一道“反演防火墙”，最大限度保护核心区信号的纯净度。
output_dir "./PNAS_Inversion_Results" 输出目录。用于存放解算后生成的 .npz 数据阵列及自动渲染的诊断图表。

3. 数值稳定与正则化参数 (Regularization Settings) 🔥【成败关键】

面对极度稀疏的单日卫星轨道，如果不加正则化，反演必然面临“数值爆炸”。本模块提供了顶刊级别的约束策略。

参数名 推荐设置 (默认) 物理/数学含义
use_normalization True 数值防爆开关。GRACE 的正演矩阵 $G$ 量级在 $10^{-9}$，而观测值 $d$ 在 $10^{-11}$。直接计算 $G^TG$ 会导致严重的截断误差和条件数爆炸。开启后，程序会将系统双向缩放至 $1.0$ 量级，这是进行高精度最小二乘求解的工业级金标准。
reg_type 'space' 或
'mixed'		 正则化平滑算子。
• 'space' (PNAS 采用)：零阶岭回归（Ridge Regression）。惩罚水质量绝对幅度的失控，但不限制相邻两天的跳跃（会产生物理上客观存在的瞬态“锯齿”）。
• 'mixed' (进阶优化)：时空混合约束。同时加入 $L_{space}$ 和一阶时间差分 $L_{time}$，在底层数学上强行约束季风洪水“渐进演化”的时间连续性。
l_space_weight 1.0 (space)
4.0 (mixed)		 空间阻尼权重。控制空间零阶约束在混合矩阵中的占比，防止信号由于防漏矩阵的串扰而向特定背景区异常堆积。

4. 超参数寻优与可视化参数 (Alpha & Plot Settings)

超参数 Alpha ($\alpha$) 决定了算法是“更相信观测数据”还是“更相信平滑约束”。

参数名 推荐设置 (默认) 物理/数学含义
alpha_method 'fixed' 或
'trace_ratio'		 寻优策略。
• 'fixed' (PNAS 采用)：使用固定的先验值。
• 'l_curve'：L曲线法（由于高频噪声，极易找不到真实拐点，不推荐）。
• 'trace_ratio' (极其强大)：基于矩阵的迹（Frobenius范数总能量），动态感知当日卫星轨道的疏密程度，自适应计算出一个让平滑约束能量占比永远恒定的动态 Alpha。
fixed_alpha 1.8 当选择 'fixed' 时的指定值。这是 PNAS 作者基于 GLDAS 水文模型闭环仿真（Closed-loop Simulation）得出的最优经验解。
smooth_ratio 0.20 当选择 'trace_ratio' 时的能量比率。设为 0.20 代表强制要求系统的平滑能量占总方程能量的 20%。
plot_spatial_dates 'all' 2D 空间地图渲染。
• []：不绘图，节省时间。
• 'all'：自动化渲染所有 15 天的九宫格空间信号分布热力图（自带核心区标签），并使用全局对齐色标（Global Vmax），极其直观地呈现洪水的空间蔓延过程。

如果你想完美复刻 PNAS Figure 4/Figure 5：请完全使用文中预设的 *实验 B (config_pnas)：开启 9-caps + reg_type = 'space' + fixed_alpha = 1.8。这能 100% 重现文献中单日瞬时反演的物理特征（包含它在单站时序图上的“锯齿”波动）。

模块二：数据降维与网格重构 (Format Conversion)

运行脚本：python export_ewhnpz_to_lgdtws_nc.py
功能描述：本模块是反演系统与形变正演系统之间的“数据桥梁”。它负责读取仅有 9 个区块数值的反演 .npz 文件，将其精准映射（Painting）到全球 $0.25^\circ \times 0.25^\circ$ 的高分辨率空间网格中，并封装成标准二维 NetCDF 格式，以便被下游的 LoadDef 前处理脚本无缝读取。

全参数详解（对应 export_npz_to_gldas_mock 函数输入）：

1. 路径与核心控制参数 (I/O & Core Controllers)

参数名 推荐设置 (默认) 物理/程序含义
npz_filepath sample_npz_path 输入文件路径。必须指向模块一跑出来的 *_data.npz 文件。程序将从中提取时间序列、9 宫格等效水高矩阵以及 9 个区域的经纬度边界框。
output_base_dir None 输出根目录。强烈建议保持默认的 None。程序会自动在输入的 .npz 文件同级目录下，创建一个独立的 LoadDef_Input_NC 文件夹，避免污染原始反演结果目录。
core_only False (常规跑)
True (对比跑)		 敏感性实验开关（高级物理功能！）。
• 设为 False 时，转换全区域（9 宫格全放进去，模拟真实的、包含外围远场水位的地球加载）。
• 设为 True 时，只转换核心区（孟加拉国），外围全部强制置 0。
👉 科研级应用：通过分别跑这两种模式并比对最终形变，你可以在论文中定量算出：“孟加拉台站的下沉，究竟有百分之多少是本地水压的，百分之多少是周边印度/缅甸水压拉扯导致的？”

2. 格式与单位伪装参数 (Format & Unit Camouflage)

参数名 推荐设置 (默认) 物理/程序含义
var_name "TWS" NetCDF 内部变量标识符。生成的 .nc 文件内部存储水质量矩阵的变量名。由于我们在后续写了专属的 read_lgd_tws.py 脚本，它默认去寻找并读取名为 'TWS' 的变量，因此这里必须保持默认值 "TWS" 才能完美对接。
unit_scale 1.0 物理单位转换因子。反演输出的原始数据 twsc_matrix_m 单位为米 (m)。由于我们专用的 read_lgd_tws.py 和底层的 LoadDef C程序最终需要的就是以“米”为单位的等效水高（EWH），因此这里保持 1.0 不变。(注：如果是为了欺骗原版 GLDAS 读取脚本，往往需要设为 1000.0 将其放大为毫米/千克每平米，但我们的优化管线已不再需要这种多余换算)。

模块三：生成负荷积分网格 (Grid Generation)

运行脚本：python gen_lgd_tws.py
功能描述：读取上一步生成的 2D NetCDF 文件，将其展平为 LoadDef 卷积程序（C/Fortran）底层要求的 1D 全球载荷阵列，并可选择性地进行空间/时间均值的扣除操作。

全参数详解（对应 USER INPUTS 区域）：

1. 路径与格式参数 (I/O & Format Parameters)

参数名 推荐设置 (默认) 物理/程序含义
lgd_directory 指向上一步的 LoadDef_Input_NC 输入目录。程序将从此路径读取由伪装脚本生成的 2D 荷载网格文件。
lgd_file_format "LGD_TWS_025DEG_%Y%m%d.nc" 文件名匹配模板。用于动态匹配每一天的文件。必须与上一步 export_ 脚本生成的文件名格式严格一致。

2. 时间区间参数 (Temporal Range Parameters)

参数名 推荐设置 (默认) 物理/程序含义
Date Range for Temporal-Mean 2020-06-01 至 2020-08-30 时间均值计算区间。如果开启了时间均值扣除（rm_temporal_mean = True），程序会提取该时间段内的所有网格来计算一条“平均参考线”。建议涵盖整个反演序列。
Date Range for Output Files 2020-06-01 至 2020-08-30 文件输出区间。实际需要导出给 LoadDef 计算形变的时间段。通常与上面的时间区间保持一致。

3. 核心算子参数 (Processing Flags) 🔥【极其致命，严禁设错】

参数名 推荐设置 (默认) 物理/数学含义
rm_temporal_mean False 时间基准线控制（最易踩坑！）。由于我们的反演数据本身就是相对于 5 月份（旱季）的纯增量，6 月初的异常本身就该是 0 附近。如果设为 True，程序会强行把这 15 天（全汛期）的平均值扣掉，导致 6 月初变成“负质量”（地壳悬空反弹），并使真实的下沉量级减半！必须设为 False 以保留真实的绝对增量。
rm_spatial_mean False 空间质量守恒控制。在进行全地球（如冰川融化引起海平面上升）研究时，常开启此项以保证全球总质量守恒。但我们做的是局部网格反演（外围背景默认填 0），强行扣除全空间均值会人为污染局部真实载荷。必须设为 False。
flip False 均值扣除顺序。决定是先扣时间均值还是先扣空间均值（False = 先时间后空间）。由于上述两项均为 False，此参数不再起作用。

4. 输出文件开关 (Output Toggles)

参数名 推荐设置 (默认) 物理/程序含义
soltag "TWS" 变量附加标签。用于生成输出文件的后缀名，方便标识该批次计算的是 Total Water Storage。
write_nc True NetCDF 导出开关。生成供 LoadDef 核心程序直接读取的高效二进制网格文件。
write_txt True 纯文本导出开关。生成 .txt 格式的网格阵列，作为后备计算方案，方便人工排查数据（包含 lat, lon, amp, phase）。
write_gmt True GMT 绘图文件开关。生成供 Generic Mapping Tools (GMT) 绘制空间分布图的坐标文件，同时会自动输出整个时间段的 _std_ (标准差) 和 _max_ (极值) 统计文件。

模块四：格林函数卷积积分 (Load Convolution)

运行脚本：mpiexec -n 4 python run_cn_lgd_tws.py (支持 MPI 多核并行)
功能描述：本模块是形变预测的“核心物理引擎”。它读取上一步生成的 1D 全球水文荷载网格，利用 PREM（初步参考地球模型）提供的负荷格林函数（Green’s Functions），通过全球球面卷积积分，计算出地表质量重新分布对指定 GNSS 台站产生的弹性三维位移（East, North, Up）。

全参数详解（对应 USER INPUTS 区域）：

1. 参考框架与地球模型参数 (Reference Frame & Earth Model)

参数名 推荐设置 (默认) 物理/程序含义
rfm "cf" 参考框架 (Reference Frame)。cf 代表 Center of Figure (地表形状中心)；cm 代表 Center of Mass (整个地球质量中心)。在与 GNSS/GPS 台站观测位移进行对比时，国际惯例和物理学标准要求统一使用 cf 框架。
pmod "PREM" 地球内部圈层模型。使用 Preliminary Reference Earth Model (初步参考地球模型) 计算的负荷乐夫数 (Load Love Numbers) 和格林函数。该模型完美模拟了地球的地壳、地幔弹性特征。
norm_flag False 格林函数归一化开关。根据提供的格林函数库格式，默认保持 False。
planet_radius 6371000. 地球平均半径。用于球面积分的底面积计算，单位为米 (m)。

2. 荷载输入与台站参数 (I/O & Station Parameters)

参数名 推荐设置 (默认) 物理/程序含义
loadfile_directory "../output/Grid_Files/nc/LGD_TWS/" 荷载网格输入目录。必须指向模块三生成的 .nc 文件存放路径。
loadfile_prefix ..._LGD_TWS_025_TWS_ 荷载文件名前缀。必须精准匹配模块三生成的文件名（注意包含日期段和均值扣除标志，如 rmTM1False）。
loadfile_format "nc" 输入文件格式。推荐使用 "nc" (NetCDF)，读取速度远快于普通文本 "txt"。
sta_file “../input/Station_Locations/BD_sites.txt” 目标台站列表。包含你想要预测形变的 GNSS 站点坐标和名称（如 BD_sites.txt）。

3. 时间区间参数 (Temporal Range)

参数名 推荐设置 (默认) 物理/程序含义
time_series True 时序模式开关。设为 True 时，程序会计算一个连续的时间序列形变，而非单帧静态形变。
frst_date
last_date		 [2020, 6, 1, 0, 0, 0]
[2020, 8, 30, 0, 0, 0]		 卷积计算时间范围。必须与模块三的输出时间段保持一致或包含于其中，格式为 [年, 月, 日, 时, 分, 秒]。

4. 核心物理与卷积参数 (Physics & Convolution Settings) 🔥【极易错】

参数名 推荐设置 (默认) 物理/数学含义
lsmask_type 0 海陆掩膜控制（极其致命！）。
• 2 代表只算陆地荷载，屏蔽海洋。
• 为什么设为 0 (全保留)？ 我们的“九宫格”反演区域南部通常覆盖了孟加拉湾（Bay of Bengal）。海面上的网格同样包含了算法分配的真实洪水/质量泄露信号，如果不设为 0 强行把海面部分屏蔽，会导致整体水质量大面积丢失，算出的地壳下沉量会严重缩水！
ldens 1000.0 载荷物质密度。因为我们输入的数据是等效水高 (EWH, 单位：米)，物质是纯水，因此密度必须严格设为 $1000 \, kg/m^3$。程序会用公式：质量 = 面积 × EWH × 密度 来计算每一格的下压重量。
mass_cons False 空间质量守恒强制开关。用于扣除空间全局均值以保证全球质量守恒。对于局部区域水文事件，强制开启会导致背景引入反向假信号，必须保持 False。
regular True 规则网格加速。我们的输入是标准的 $0.25^\circ \times 0.25^\circ$ 等经纬度网格，开启此项可极大加速底层插值与球面积分速度。

5. 计算网格优化参数 (Integration Mesh Parameters)

参数名 推荐设置 (默认) 物理/程序含义
common_mesh False 通用积分网格开关。设为 False 时，程序会针对每一个特定的 GNSS 台站（Station），以该台站为中心动态生成自适应的同心圆积分网格（Station Mesh）。离台站越近的地方网格划分越密，越远越疏。这比使用全球统一网格 (True) 的计算精度高出数倍，是局部高精度形变计算的黄金标准！

模块五：时序可视化与物理分析 (Visualization)

运行脚本：python plot_ts.py
功能描述：本模块是整套反演与形变系统的“最终显示终端”。它负责读取上一模块（卷积计算）输出的 GNSS 台站形变时序文本文件，将内部的振幅（Amplitude）和相位（Phase）还原为真实的每日物理位移量，并绘制出顶刊级别的三维（East, North, Up）弹性形变时间序列图。

全参数详解（对应脚本顶部 Input Parameters 区域）：

1. 台站与文件匹配参数 (Station & I/O Parameters)

参数名 推荐设置 (示例) 物理/程序含义
station "PUST" 或 "SNT1" 目标台站名称。指定你需要进行读取和可视化的特定 GNSS 站点标识符（通常为 4 字符代码）。需确保该台站在模块四中已成功完成卷积计算。
filename 动态拼接字符串 目标文件名。严格记录了该数据的前世今生：包含了台站名、参考框架(cf)、数据源(LGD_TWS)、均值扣除标志(rmTM1False)、时间段以及地球模型(PREM)。必须与模块四输出在 output/Convolution/ 目录下的 .txt 文件名完全咬合！
ts_file "../../output/..." 输入文件绝对/相对路径。定义读取时序文本数据的具体位置。

2. 核心信号处理参数 (Signal Processing) 🔥【极具欺骗性，严禁设错】

参数名 推荐设置 (默认) 物理/数学含义
detrend False 线性去趋势开关（最致命的画图陷阱！）
• scipy.signal.detrend 的数学原理是：拟合一条最小二乘直线并将其从数据中减去。
• 物理危害：季风大洪水是一个持续 2-3 个月的“质量单向累积”过程，形变时序图将会呈现出真实的、一路向下的“负向倾斜趋势”。如果强行开启 True，代码会把这条下坡线拉平，导致 6 月原本正常的 0 mm 被强行压成负数，8 月的巨大下沉被强行翘成“地壳反弹”（正数），彻底摧毁物理真相！
• 科研铁律：在研究短周期的单次极端气候/地质事件时，必须永久设为 False！只有在处理包含数年数据的长序列（为消除板块构造长年漂移）时，才会开启此项。

4. 数据结果的正确性验证 (How to Interpret the Results)

当你正确配置了上述所有参数后，你的最终结果应满足以下三大物理特征，这也是完美对标 PNAS 2021 顶刊结果的铁证：

  1. 绝对基准归零 (Baseline at Zero)

    • 现象：Up 分量在 6 月初严格处于 0 mm 附近。
    • 原因：这证明 rm_temporal_mean = False 成功保留了相对于旱季 5 月的绝对质量增量，地壳尚未受压。

  2. 量级与相位精确咬合 (Magnitude and Phase Match)

    • 现象：Up 分量在 7 月下旬一路跌至 -6 到 -8 mm，随后逐渐回升。
    • 原因：这证明 detrend = False 保护了真实的物理极值。约 75 Gt 的巨大质量导致地壳弹性形变达 ~7 mm，与 PNAS 报告的数据严丝合缝。

  3. 北向拉扯效应 (Horizontal Pulling)

    • 现象：North 分量在洪水期出现了约 +2 mm 的显著爬升。
    • 原因：孟加拉国洪水核心区位于中北部。巨大的北部质量聚集不仅把地壳往下压，还通过万有引力及地壳形变将南部的台站向北拉扯。这是力学加载模型极为优美的自然响应！

💡 附：消除单站锯齿的终极技巧 (Spatial Averaging)

在瞬时反演模式下，单站曲线存在日际跳跃（锯齿）是稀疏轨道带来的必然物理噪声。为了获得发表级别的平滑图表：

  • 解决方案：将选定区域内的多个 GNSS 站点（如 8 个站）的每日 Up 值求算术平均。空间平均将完美抵消九宫格内部的质量“晃动噪声”，呈现出平滑顺畅的 U 型沉降曲线。
